AUDIT OF THE FACT->NAME MAPPING (second mind)

Per-axis verdicts:
1. SELF-KEYED — WEAK. The fact "metric strictly increasing in knob [0.9, 0.95, 0.99]; knob_kind undeclared" establishes monotonicity in a knob of undeclared kind, but SELF-KEYED (per NOT-SELF-KEYED) requires the knob to be the mechanism's OWN lever; the check's N/A carve-out for workload/instrument knobs shows kind matters, yet an undeclared kind is treated as self-keyed. The fact under-determines the name; if the knob's true kind is workload/instrument, fact and name are co-wrong in the same direction (a co-error the battery can't see). (SR4's SELF-KEYED half inherits this.)
2. NULL-REACHES-HEADLINE — CONFIRM. The F2 fact "null 0.3 >= mechanism 0.1" cleanly instantiates "a null reaches/exceeds the mechanism's headline" (the BEATS-NULL failure). Caveat: the axis groups 8 refinement-axis fire cells that share the identical "null >= mechanism" fact, so the refinement distinctions live only in cell-name annotations, not re-derivable facts.
3. CONFOUNDED — CONFIRM. The fact "no null holds the substrate; best null drops ['bus','shared'] beyond the lever 'cm'" instantiates the ISOLATED failure: the null differs from the mechanism in more than the mechanism's own lever.
4. WRONG-AXIS — WEAK. The fact "mechanism at/below null on its own axis (0 <= 0)" is a tie — the weakest CO-MOVES failure — and under-determines the name WRONG-AXIS, which asserts the mechanism is on the wrong axis, a stronger claim than "doesn't beat the null on its own axis."
5. WITHIN-NOISE — CONFIRM. The fact "null 0.35 inside mechanism CI (lo 0.3)" instantiates the NOISE-FLOOR failure: the null's value is inside the mechanism's CI, so the point beat is not resolvable.
6. CONSEQUENCE-WITNESSED — CONFIRM. The fact "witness observes only consequences (['runtime timing','output quality']), never the referent 'the cache is correct'" cleanly instantiates the REFERENT-WITNESSED failure.
7. LOSSY-PROJECTION — CONFIRM. The fact "record(s) ['L'] map to >1 referent value: {'L': {0.0, 1.0}}" cleanly instantiates the many-to-one lossy-projection failure (the referent is non-identifiable from the record).
8. SELECTION-BIAS — WEAK. The fact "headline 2.75 is the max of 4 independent draws of a fixed instrument (knob [0.9])" is a plausible selection-bias fact (best-of-N max selection), but SELECTION-BIAS has NO definition in the inspectable surface: axis_defs.txt is truncated mid-definition and "selection" appears 0 times (primary-axis numbering jumps 5th -> 6th -> 8th). The second mind cannot audit the mapping because the definition is absent.
9. AGGREGATION-REVERSAL — CONFIRM. The fact "within-subgroup unanimous {'A': 1, 'B': 1} but pooled reverses to -1 (Simpson)" cleanly instantiates the Simpson's-paradox / aggregation-reversal failure (unanimous within-subgroup direction reversed by the pooling weights).

Fragile axes:
The two most fragile mappings are SELECTION-BIAS and SELF-KEYED. SELECTION-BIAS is the most fragile because its definition is missing from the inspectable surface entirely — axis_defs.txt is cut off mid-sentence (ending at "METRIC-ONSET / METRIC-SPIKE ... so for a metric-scoped claim it") and the 7th primary axis never appears, so a second mind has no definition against which to check whether "headline = max of 4 draws" instantiates the author's concept of selection bias; the mapping is asserted, not inspectable. SELF-KEYED is fragile because the fact rests on an unexamined assumption: the check treats an undeclared knob_kind as the mechanism's own lever, but the definition's own N/A carve-out (workload/instrument knobs) shows kind is load-bearing, and an undeclared kind is not established to be the mechanism's own lever — so the fact under-determines the name, and if the knob is actually a workload knob, fact and name are co-wrong in the same direction (the battery stays green). WRONG-AXIS is a weaker third: its fact is a tie (0 <= 0), the weakest CO-MOVES failure, which under-determines the stronger "wrong-axis" label.

The table is a fair inspectable surface for the eight axes whose definitions are present — the mechanical facts are specific enough to confirm or refute each fact->name mapping — but it hides the judgment for SELECTION-BIAS, whose definition is absent from the truncated axis_defs.txt, so a second mind cannot audit that mapping at all.
