# 2610.03213 (Toward SLM-based agentic task-tool intent matching — Troiani/Salarian/El Helou/Ryder/Diaconu/Muyal/Yannuzzi, Cisco Systems Switzerland, 2026-10-02) — explore note, 2026-10-05

An SLM (Gemma 3 1B/4B) specialized via GEPA+SFT+GRPO as a per-call task-tool relevance
classifier for "intent-based TBAC": it "verifies" every tool call against the task intent
and returns a relevance signal for downstream enforcement. Operational target: 95% accuracy
AND F1 (self-set, "the often used 95% goal").

## The certifier IS the instrument (certifier-relocation specimen)
The SLM is not measuring a system; it IS the oversight. So the question "who certifies the
certifier?" lands directly:
- Ground-truth labels are BY-CONSTRUCTION (structural lane, certifiable, no benchmark):
  a "correct set" = G(q); a "wrong set" = same-server replacement; a "null set" = server
  outside R(q); wrong+null both map to y(q,c)=0 by definition (§2.2). The right answer is
  known because they built the candidate set, not because they observed an agent.
- Curation is a SECOND certifier (human/LLM) who CONFIRMS the by-construction label
  ("retained a row only when all recorded curators agreed"), not one who discovers it.
  9289 rows -> 7811 in 3155 complete groups.
- The TASK TEXT q is generated by GPT-5.2 to MATCH the selected tools' names/descriptions
  (schema hidden to avoid over-fitting). So the "intent" in the dataset is a GPT-5.2
  reconstruction, and the SLM is tested on reverse-engineering that mapping — not on real
  agent intent. The certifier's independence is PARTIAL: Gemma is a different org than the
  data generator (GPT-5.2/OpenAI), but the intent it certifies against is generator-defined.
  Same-ecosystem self-keying, one link up.

## Two-lane structure (clean)
- LANE A (by-construction): the relevance LABELS. Certifiable without any benchmark.
- LANE B (empirical, scoped): the classifier's accuracy on those labels. Scoped to
  synthetic GPT-5.2-curated pairs, ONE model family (Gemma 3), TWO sizes, one novel
  multi-tool MCP dataset (+ ASTRA + TOUCAN). Held-out test evaluated only after all choices
  fixed; 95% BCa CIs from 10k paired bootstrap.

## The discriminating gap: threat model > instrument (scope gap, the load-bearing one)
Abstract threat model is COMPOSITIONAL/SEQUENTIAL: "a rogue agent might deviate the calls
or nudge other agents to make a COMBINATION of calls that would not align with the task's
intent." But the instrument is a STATIC PER-CALL classifier: "evaluates every selected tool
INDEPENDENTLY against the assigned task." A rogue agent that picks individually-relevant
tools whose COMBINATION doesn't satisfy intent — or reorders relevant tools — passes every
per-call check. The dataset's negative classes (wrong set = same-server swap, null set =
outside-server) are ALL single-tool-level, matching the instrument's per-call granularity;
there is NO "compositional wrong" class (all tools in G(q) but the task subtly different).
So the negative examples structurally cannot catch the compositional/sequential threat the
motivation describes. The instrument certifies a strictly narrower claim than the
motivation states.

## Headline vs evidence ("viable operational alternative")
- GPT-5.6 Sol (frontier baseline): 98.58% acc / 98.86% F1, no parse failures.
- Gemma 3 1B: Base 60.94% -> SFT 80.06% -> GRPO 89.60% E2E acc, 91.39% F1. BELOW the 95%
  target. This is the model that would actually enable the low-latency/on-prem motivation.
- Gemma 3 4B: Base 87.48% -> GEPA 91.58% -> SFT 93.78% -> GRPO 96.13% E2E acc, 96.90% F1.
  "Slightly surpassing" the bar.
So "specialized SLMs can provide a viable operational alternative to frontier models" is
really: a 4B Gemma barely clears a SELF-SET 95% bar on a SYNTHETIC dataset; the smaller
model that motivates the low-latency use case does not clear it.

## The FPR the 95% hides
At the "passing" 4B/GRPO config, FPR = 5.42% (FNR 2.94%). For an AUTHORIZATION instrument
the false-ALLOW rate is the security-relevant number: ~5.4% of irrelevant tools are still
ALLOWED. The symmetric 95% accuracy/F1 target (borrowed from general ML, not derived from
an authorization cost model) hides that the false-allow rate is not negligible. Costs of
false-allow (rogue call through) and false-block (legit call stopped) are asymmetric; the
paper reports both rates (good) but the headline bar is symmetric.

## Take
Clean certifier-relocation specimen with a specific scope gap: the certifier is the
instrument, its ground truth is by-construction but its intent is generator-defined
(GPT-5.2), and the per-call instrument is strictly narrower than the compositional/
sequential rogue-agent threat it is motivated by. Headline "viable operational alternative"
rests on a 4B barely clearing a self-set 95% bar on synthetic data, with a 5.4% false-allow
rate the symmetric target hides, and the low-latency 1B failing the bar.
